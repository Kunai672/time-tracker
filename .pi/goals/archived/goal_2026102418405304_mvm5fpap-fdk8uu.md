# Goal Prompt

Objective: Build a client-only time tracker web app in this repo using Next.js (App Router, TypeScript). All data persists in localStorage. There is no backend and no auth. Work through the phases in order. Each phase must leave npm run lint && npm run typecheck && npm test && npm run build passing before the next begins.

Constraints

No new dependencies except recharts, which is allowed for charts only.
All localStorage access goes through a single module at lib/storage.ts. It must be SSR-safe and use a versioned schema.
Business logic (validation, duration math, aggregation, filtering) lives in pure functions with unit tests. UI components only call these.
Never weaken or delete existing tests to make them pass.
Do not git commit or push. Append a short note to .agent/PROGRESS.md after each phase.

Phases and acceptance criteria

Storage layer: lib/storage.ts exports typed load, save and migrate. It returns defaults on empty or corrupt data and doesn’t throw when window is undefined. Tests cover empty, corrupt and versioned data.
Models: TimeEntry (id, description, categoryId, start, end, durationMinutes) and Category (id, name, color). Validation rejects end before start and empty names. Duration helpers have unit tests.
Categories CRUD: Create, rename, recolor and delete. Deleting a category reassigns its entries to “Uncategorized” rather than orphaning them. This is tested.
Entries CRUD: An entries page to add, edit and delete entries, sorted newest first. Component tests cover add, edit and delete.
Live timer: Start and stop a timer for a category. A running timer survives a page reload, and stopping it creates an entry. The time source is injectable so tests are not flaky.
Filters: Filter entries by date range and category. A pure filterEntries function is tested at the boundaries.
Daily chart: A bar chart of hours per day for the filtered range, driven by a tested aggregateByDay function. An empty state is shown when there is no data.
Category chart: A donut or pie of time per category using a tested aggregateByCategory. It reuses the filters from phase 6.
Export / import: JSON export, and import with schema validation that rejects malformed files without touching existing data.

Done when: all nine phases are complete, the full verify command passes on a clean checkout, and the app builds. The auditor should confirm each criterion against the code and tests, not the agent’s own claims.
